# BusinessSuite.Infrastructure

Technical implementations: SQL Server through EF Core, ASP.NET Core Identity persistence, and later
e-mail, file storage, payment-provider and tax-authority (e.g. FBR digital invoicing) adapters.

| Belongs here | Never here |
|---|---|
| `AppDbContext`, entity configurations, migrations | Business rules (they belong in Domain / Application) |
| EF Core interceptors (auditing, later tenant checks) | Controllers, views, view models |
| Identity user/role classes and sign-in rules | Hard-coded connection strings or secrets |
| Implementations of Application interfaces | References to the Web project |

## Folder map

```text
Diagnostics/
  HealthCheckTags.cs              "ready" tag used by /health/ready
Identity/
  ApplicationUser.cs              Identity user + DisplayName, IsActive, audit stamps
  ApplicationRole.cs              Platform-level role
  ApplicationSignInManager.cs     Blocks sign-in for deactivated users
  ApplicationUserClaimsPrincipalFactory.cs  Adds display name to the cookie
Persistence/
  AppDbContext.cs                 The EF Core context (one per application)
  DatabaseOptions.cs              "Database" settings + connection string
  DatabaseInitializer.cs          Development only: migrate + seed
  DatabaseSchemas.cs              SQL schema names per module
  Configurations/                 One IEntityTypeConfiguration<T> per entity (auto-discovered)
  Interceptors/                   AuditableEntityInterceptor (Created/Updated stamps)
  Migrations/                     Generated by `dotnet ef` (see README inside)
  Seeding/                        Development user seeding (no default credentials)
InfrastructureServiceCollectionExtensions.cs   AddInfrastructure(): the registration list
```

## Adding a table

1. Create the entity in `BusinessSuite.Domain/<Module>/`.
2. Add `Persistence/Configurations/<Entity>Configuration.cs` implementing `IEntityTypeConfiguration<T>`
   (table name + schema, lengths, required fields, indexes, relationships with explicit `OnDelete`).
3. Add `public DbSet<T> <Plural> => Set<T>();` to `AppDbContext`.
4. Run `./scripts/db.ps1 add <MigrationName>`, review the generated file, run the tests, commit.

Detailed walkthrough: `docs/DEVELOPER_GUIDE.md`.
