# Developer guide

The handbook for maintaining and extending BusinessSuite **without outside help**. It explains the
framework building blocks, gives copy-paste recipes for common changes, and shows how to debug.

Contents: [1. Mental model](#1-mental-model) · [2. Conventions](#2-conventions) ·
[3. Building blocks](#3-building-blocks) · [4. Recipes](#4-recipes) · [5. Debugging](#5-debugging) ·
[6. Where to change what](#6-where-to-change-what)

## 1. Mental model

```text
Browser
  │  HTTPS request (cookie identifies the user)
  ▼
Program.cs pipeline ── correlation id → errors → security headers → routing → rate limit → auth → authorization
  ▼
Controller (Web)            thin: validates input shape, calls ONE service, picks the view/redirect
  ▼
Application service         the use case: business validation, permissions, returns Result / DTO
  ▼
Domain entities             rules that keep data valid (methods, not setters)
  ▼
AppDbContext (Infrastructure) → EF Core → SQL Server
```

Three questions decide where code goes:

| Question | Goes in |
|---|---|
| Is it a rule of the business (e.g. "stock cannot go negative", "a paid invoice cannot be edited")? | Domain entity method, or Application service if it needs data |
| Is it about HTTP, HTML, cookies, redirects or display formatting? | Web (controller, view model, view) |
| Is it about SQL, EF Core, Identity storage, files, e-mail, external APIs? | Infrastructure (behind an Application interface) |

## 2. Conventions

| Item | Convention | Example |
|---|---|---|
| Namespaces | Match the folder, file-scoped | `namespace BusinessSuite.Application.Features.Dashboard;` |
| One type per file | File name = type name | `DashboardService.cs` |
| Service interface / implementation | `I<Feature>Service` public, `<Feature>Service` internal sealed | `IDashboardService`, `DashboardService` |
| Data returned by services | `<Thing>Dto` or a descriptive record | `DashboardOverview` |
| Input for a change | `<Verb><Thing>Command` | `CreateProductCommand` |
| View models | `<Page>ViewModel` in `Web/Models/<Feature>/` | `LoginViewModel` |
| Entity configuration | `<Entity>Configuration` | `ApplicationUserConfiguration` |
| Async methods | `...Async` + `CancellationToken cancellationToken = default` as last parameter | `GetOverviewAsync(ct)` |
| Instants | `DateTimeOffset` UTC, suffix `AtUtc` | `CreatedAtUtc` |
| Money | `decimal`, never `double`/`float` | `UnitPrice` |
| Error codes | `<Area>.<Reason>` | `Product.DuplicateSku` |
| Tests | Sentence names with underscores; Arrange / Act / Assert | `Deactivated_users_cannot_sign_in` |
| Comments | Explain **why**, not what. XML `<summary>` on public framework types. | |

Rules that tests enforce automatically: layer dependencies (`LayerDependencyTests`), controllers inherit
`AppController` and never take `AppDbContext`, only approved actions are anonymous (`ControllerConventionTests`),
the model has a migration (`MigrationTests`).

## 3. Building blocks

### Domain (`src/BusinessSuite.Domain/Common`)

| Type | Use |
|---|---|
| `Entity` | Base class with `Guid Id` (generated by EF Core on insert). |
| `AuditableEntity` | `Entity` + `CreatedAtUtc/ByUserId`, `UpdatedAtUtc/ByUserId`, filled automatically on save. Use for almost every business entity. |
| `IAuditable` | Implement directly when you cannot inherit `AuditableEntity` (e.g. `ApplicationUser`). |
| `DomainException` | Throw when an entity would become invalid. User-facing validation belongs in services (`Result`). |

### Application (`src/BusinessSuite.Application/Common`)

| Type | Use |
|---|---|
| `Result`, `Result<T>`, `Error`, `ErrorType` | Return expected failures. `return Error.NotFound("Product.NotFound", "Product not found.");` and `return product.Id;` both convert implicitly. |
| `PageRequest`, `PagedResult<T>` | Every list is paged. `PageRequest` clamps bad input (page ≥ 1, size 1–100). |
| `ICurrentUser` | Who is calling (`UserId`, `UserName`, `DisplayName`; organization from Phase 2). Inject it; never read `HttpContext` in Application. |
| `TimeProvider` | Inject for "now" (`timeProvider.GetUtcNow()`); tests use `FixedTimeProvider`. Never call `DateTime.Now`. |
| `ApplicationOptions` | Example of a validated settings class (`IValidatableObject` for custom checks). |
| `AppClaimTypes`, `PlatformRoles` | Names shared by Web and Infrastructure. |

### Infrastructure (`src/BusinessSuite.Infrastructure`)

| Type | Use |
|---|---|
| `AppDbContext` | The only DbContext. Add `DbSet`s per aggregate root. Configurations are auto-discovered. |
| `AuditableEntityInterceptor` | Fills audit stamps; protects "created" values on update. |
| `DatabaseOptions` | Connection string + database settings (validated). |
| `DatabaseInitializer`, `DevelopmentUserSeeder` | Development-only migrate + seed. |
| `ApplicationUser`, `ApplicationRole`, `ApplicationSignInManager` | Identity customisation (display name, active flag, sign-in rule). |

### Web (`src/BusinessSuite.Web/Framework`)

| Type / file | Use |
|---|---|
| `AppController` | Base for all controllers: `NotifySuccess/Info/Warning/Error`, `RedirectToLocal`, `AddErrorToModelState(error)`, `ErrorResult(error)`. |
| `TempDataAlertExtensions` + `_Alerts.cshtml` | One-time messages after a redirect. |
| `PageViewDataExtensions` + `_Breadcrumbs.cshtml` | `ViewData.SetPageTitle(...)`, `ViewData.AddBreadcrumb(...)` at the top of a view. |
| `_FormErrors.cshtml` | `<partial name="_FormErrors" />` inside forms shows form-level errors. |
| `NavigationMenu` | The sidebar and dashboard module list. Add/enable modules here. |
| `NavigationAuthorizer` | Filters menu items by policy (used by sidebar and dashboard). |
| `AuthorizationPolicies` | Policy names; register new policies in `AddAuthorizationPolicies`. |
| `RateLimitingPolicies` | `[EnableRateLimiting(RateLimitingPolicies.Login)]` on sensitive POST actions. |
| `CorrelationIdMiddleware` | `HttpContext.GetCorrelationId()` returns the request's reference id. |
| `SecurityHeadersMiddleware` | CSP and other headers; value of CSP in configuration. |
| `HealthEndpointExtensions` | `/health/live`, `/health/ready`. |
| `AppInfo.Version` | Version shown on the dashboard (from `Directory.Build.props`). |

## 4. Recipes

Each recipe lists files in the order you create them. Build and run the tests after each recipe.

### R1. Add a configuration setting

1. Add a property to an existing settings class, or create one next to the code that uses it:

```csharp
// src/BusinessSuite.Application/Common/Options/InvoicingOptions.cs
using System.ComponentModel.DataAnnotations;

namespace BusinessSuite.Application.Common.Options;

public sealed class InvoicingOptions
{
    public const string SectionName = "Invoicing";

    [Range(1, 365)]
    public int DefaultPaymentTermDays { get; set; } = 30;
}
```

2. Register it in `AddApplication()`:

```csharp
services.AddOptions<InvoicingOptions>()
    .BindConfiguration(InvoicingOptions.SectionName)
    .ValidateDataAnnotations()
    .ValidateOnStart();
```

3. Add the default to `appsettings.json` (`"Invoicing": { "DefaultPaymentTermDays": 30 }`) and a row to `docs/CONFIGURATION.md`.
4. Inject `IOptions<InvoicingOptions>` where needed and read `.Value`.

### R2. Add an entity and its table

```csharp
// 1. src/BusinessSuite.Domain/Catalog/Category.cs
using BusinessSuite.Domain.Common;

namespace BusinessSuite.Domain.Catalog;

public sealed class Category : AuditableEntity
{
    public const int NameMaxLength = 100;

    private Category() { } // for EF Core

    public Category(Guid organizationId, string name)
    {
        OrganizationId = organizationId;
        Rename(name);
    }

    public Guid OrganizationId { get; private set; }
    public string Name { get; private set; } = string.Empty;
    public bool IsActive { get; private set; } = true;

    public void Rename(string name)
    {
        ArgumentException.ThrowIfNullOrWhiteSpace(name);
        if (name.Length > NameMaxLength) throw new DomainException($"Category name cannot exceed {NameMaxLength} characters.");
        Name = name.Trim();
    }

    public void Deactivate() => IsActive = false;
}
```

```csharp
// 2. src/BusinessSuite.Infrastructure/Persistence/Configurations/CategoryConfiguration.cs
using BusinessSuite.Domain.Catalog;
using Microsoft.EntityFrameworkCore;
using Microsoft.EntityFrameworkCore.Metadata.Builders;

namespace BusinessSuite.Infrastructure.Persistence.Configurations;

internal sealed class CategoryConfiguration : IEntityTypeConfiguration<Category>
{
    public void Configure(EntityTypeBuilder<Category> builder)
    {
        builder.ToTable("Categories", "catalog");     // add "catalog" to DatabaseSchemas.cs
        builder.Property(c => c.Name).HasMaxLength(Category.NameMaxLength).IsRequired();
        builder.HasIndex(c => new { c.OrganizationId, c.Name }).IsUnique();
    }
}
```

3. In `AppDbContext`: `public DbSet<Category> Categories => Set<Category>();`
4. `./scripts/db.ps1 add AddCategories`, review the migration, run the app (applies it), run the tests, commit.

### R3. Add an application service (a use case)

```csharp
// src/BusinessSuite.Application/Features/Catalog/ICategoryService.cs
public interface ICategoryService
{
    Task<Result<Guid>> CreateAsync(CreateCategoryCommand command, CancellationToken cancellationToken = default);
}

public sealed record CreateCategoryCommand(string Name);
```

```csharp
// src/BusinessSuite.Application/Features/Catalog/CategoryService.cs
internal sealed class CategoryService(IAppDbContext db, ICurrentUser currentUser) : ICategoryService
{
    public async Task<Result<Guid>> CreateAsync(CreateCategoryCommand command, CancellationToken cancellationToken = default)
    {
        if (string.IsNullOrWhiteSpace(command.Name))
        {
            return Error.Validation("Category.NameRequired", "Enter a category name.");
        }

        // From Phase 2 the organization comes from ICurrentUser, never from the request.
        var organizationId = currentUser.OrganizationId!.Value;

        var exists = await db.Categories.AnyAsync(c => c.OrganizationId == organizationId && c.Name == command.Name.Trim(), cancellationToken);
        if (exists)
        {
            return Error.Conflict("Category.DuplicateName", "A category with this name already exists.");
        }

        var category = new Category(organizationId, command.Name);
        db.Categories.Add(category);
        await db.SaveChangesAsync(cancellationToken);
        return category.Id;
    }
}
```

Register in `AddApplication()`: `services.AddScoped<ICategoryService, CategoryService>();`
Unit-test the rules; integration-test the data access with `[SqlServerFact]`.
(`IAppDbContext` and `ICurrentUser.OrganizationId` arrive in Phase 2 — see the roadmap.)

### R4. Add a page

```csharp
// src/BusinessSuite.Web/Controllers/ReportsController.cs  (or an Area, see R7)
public sealed class ReportsController(IReportService reports) : AppController
{
    [HttpGet]
    public async Task<IActionResult> Index(CancellationToken cancellationToken)
    {
        var data = await reports.GetSummaryAsync(cancellationToken);
        return View(ReportsIndexViewModel.From(data));
    }
}
```

```cshtml
@* src/BusinessSuite.Web/Views/Reports/Index.cshtml *@
@model ReportsIndexViewModel
@{
    ViewData.SetPageTitle("Reports");
    ViewData.AddBreadcrumb("Reports");
}
<div class="page-header"><h1 class="page-title">Reports</h1></div>
```

Then enable the menu item in `NavigationMenu` (set `Controller: "Reports"`, remove `Status: ModuleStatus.Planned`)
and add an integration test with `factory.CreateSignedInClient()` that expects 200.

### R5. Add a form that changes data (Post/Redirect/Get)

```csharp
[HttpGet]
public IActionResult Create() => View(new CategoryFormViewModel());

[HttpPost]
public async Task<IActionResult> Create(CategoryFormViewModel model, CancellationToken cancellationToken)
{
    if (!ModelState.IsValid)
    {
        return View(model);                               // field errors shown by asp-validation-for
    }

    var result = await categories.CreateAsync(new CreateCategoryCommand(model.Name), cancellationToken);
    if (result.IsFailure)
    {
        AddErrorToModelState(result.Error);               // shown by <partial name="_FormErrors" />
        return View(model);
    }

    NotifySuccess("Category created.");
    return RedirectToAction(nameof(Index));               // never return a view after a successful POST
}
```

```cshtml
<form asp-action="Create" method="post" data-disable-on-submit>
    <partial name="_FormErrors" />
    <div class="mb-3">
        <label asp-for="Name" class="form-label"></label>
        <input asp-for="Name" class="form-control" />
        <span asp-validation-for="Name" class="text-danger small"></span>
    </div>
    <button type="submit" class="btn btn-primary">Save</button>
</form>
@section Scripts { <partial name="_ValidationScriptsPartial" /> }
```

The `<form asp-...>` tag helper adds the anti-forgery token automatically; the global filter rejects POSTs without it.
`data-disable-on-submit` prevents double submission.

### R6. Protect a page with a policy

1. Add the name to `AuthorizationPolicies` and register it in `AddAuthorizationPolicies()`:
   `.AddPolicy(AuthorizationPolicies.ManageCatalog, p => p.RequireAuthenticatedUser().RequireRole(...))`.
2. Put `[Authorize(Policy = AuthorizationPolicies.ManageCatalog)]` on the controller or action.
3. Set `Policy: AuthorizationPolicies.ManageCatalog` on the menu item (visibility only).
4. Add an integration test: a user without the role gets redirected to `/Account/AccessDenied`.

### R7. Add a module as an MVC Area

```text
src/BusinessSuite.Web/Areas/Inventory/Controllers/StockController.cs    [Area("Inventory")] on the class
src/BusinessSuite.Web/Areas/Inventory/Views/_ViewImports.cshtml          copy of Views/_ViewImports.cshtml
src/BusinessSuite.Web/Areas/Inventory/Views/_ViewStart.cshtml            @{ Layout = "_Layout"; }
src/BusinessSuite.Web/Areas/Inventory/Views/Stock/Index.cshtml
```

URL: `/Inventory/Stock`. Menu item: `Controller: "Stock", Area: "Inventory"`. Links: `asp-area="Inventory"`.

### R8. Write tests

| Kind | Where | Template |
|---|---|---|
| Unit (rules, services) | `tests/BusinessSuite.Tests.Unit/<Layer>/<Feature>/` | `DashboardServiceTests` (fakes in `TestDoubles/`) |
| Web behaviour (no database) | `tests/BusinessSuite.Tests.Integration/Web/` | `AuthenticationTests` (`IClassFixture<BusinessSuiteWebApplicationFactory>`) |
| Data access (SQL Server) | `tests/BusinessSuite.Tests.Integration/<Feature>/` | `AuditingTests`, `SignInTests` (`[SqlServerFact]`) |

Always add the negative case next to the happy path: invalid input, missing permission, another organization's id.

## 5. Debugging

### Start the app under the debugger

* **Visual Studio:** open `BusinessSuite.sln`, set `BusinessSuite.Web` as start-up project, choose the `https` profile, press F5.
* **VS Code:** open the folder, install the recommended extensions, press F5 ("BusinessSuite.Web (https)").
* Breakpoints work in controllers, services, middleware and Razor views (`.cshtml` code blocks).
* Debug tests: Test Explorer (VS / VS Code) → right-click a test → Debug.

### Read the logs

* The console (VS: Output window → "BusinessSuite.Web"; VS Code: Debug Console/terminal) shows every log line
  with its correlation id.
* A user reports an error page with "Reference: 3f2a..." → search the logs for that value to find the exception and
  the request that caused it.
* See the SQL sent to the database: Development already logs it (category `Microsoft.EntityFrameworkCore.Database.Command`).
  To include parameter values temporarily: set `Database:EnableSensitiveDataLogging` to `true` in user-secrets.

### Development vs production error pages

* Development shows the detailed Developer Exception Page (stack trace, query, headers).
* To see what customers see, run with `--environment Production`:
  `dotnet run --project src/BusinessSuite.Web -- --environment Production` (needs a connection string available to Production, e.g. an environment variable).

### Inspect the database

SQL Server Management Studio or the VS Code "SQL Server (mssql)" extension → server `(localdb)\MSSQLLocalDB` →
database `BusinessSuite_Dev` → schema `identity`. Check applied migrations: `SELECT * FROM __EFMigrationsHistory`.

### Typical problems while developing

| Symptom | Look at |
|---|---|
| New page returns 404 | Controller name ends with `Controller`, inherits `AppController`, action is public; Areas need `[Area("...")]` |
| Form POST returns 400 | The form is not built with `<form asp-...>` (missing anti-forgery token), or you are on `http://` instead of `https://` |
| Page looks unstyled / button does nothing | Browser console (F12): a CSP error means an inline script/style — move it into `wwwroot/js` or `wwwroot/css` |
| App stops at start-up with `OptionsValidationException` | The message names the invalid setting; fix it in appsettings or user-secrets |
| "Unable to resolve service for type ..." at start-up | The service is not registered in `AddApplication`/`AddInfrastructure`/`AddWebPresentation` |
| Changes in a `.cshtml` not visible | Use `dotnet watch`, or rebuild |

More: [TROUBLESHOOTING.md](TROUBLESHOOTING.md).

## 6. Where to change what

| I want to change... | File |
|---|---|
| Order of middleware, routes | `src/BusinessSuite.Web/Program.cs` |
| Service registrations | `ApplicationServiceCollectionExtensions.cs`, `InfrastructureServiceCollectionExtensions.cs`, `Framework/Hosting/WebServiceCollectionExtensions.cs` |
| Password, lockout rules | `InfrastructureServiceCollectionExtensions.AddIdentityServices` or the `Identity` config section |

| Package versions | `Directory.Packages.props` |
| Target framework, warnings | `Directory.Build.props` |
