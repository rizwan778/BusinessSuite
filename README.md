# BusinessSuite

A multi-tenant business management SaaS for wholesalers, distributors and retailers: inventory,
purchasing, sales and invoicing, customers, expenses, reporting, and subscription billing.
The first target market is FMCG trade in Pakistan (including FBR digital invoicing later), but nothing
in the core is tied to one industry or country: currency, time zone, tax rules and features are configuration.

Built as a **modular monolith** on ASP.NET Core MVC (.NET 10), SQL Server and EF Core, with a small
in-house framework layer so the code can be debugged, maintained and extended by people working offline.

> **Status: Phase 1 · Foundation.** The project skeleton, security baseline, sign-in, dashboard shell,
> tests, CI and documentation exist. Business modules (products, stock, invoices, ...) are planned and
> shown as "Phase N" in the menu. See [docs/IMPLEMENTATION_ROADMAP.md](docs/IMPLEMENTATION_ROADMAP.md).

## What works today

| Area | Implemented in Phase 1 |
|---|---|
| Structure | Domain / Application / Infrastructure / Web projects, enforced by architecture tests |
| Sign-in | ASP.NET Core Identity on SQL Server, MVC login/logout, lockout, rate limiting, deactivated-user block |
| Security | Secure-by-default authorization, CSRF tokens, strict Content-Security-Policy, security headers, HTTPS/HSTS, `__Host-` cookies |
| UI | Responsive Bootstrap 5 layout: sidebar, top bar, breadcrumbs, alerts, dashboard, friendly error pages (works offline, no CDN) |
| Operations | Structured logging with correlation ids, `/health/live` and `/health/ready`, validated configuration |
| Data | `AppDbContext`, Identity tables in the `identity` schema, automatic created/updated audit stamps |
| Quality | 90+ automated tests, GitHub Actions CI with a real SQL Server |

Not yet implemented (planned): organizations and tenant isolation, user management, subscriptions,
all business modules, reports, PDF invoices, payments, e-mail. Nothing in this repository claims otherwise.

## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| .NET SDK | 10.0.100 or newer 10.0 SDK | `dotnet --list-sdks`. Pinned by `global.json` (later 10.0 feature bands are accepted). |
| SQL Server | LocalDB, Express or Developer (all free) | LocalDB comes with Visual Studio; or use Docker (`tools/sqlserver/docker-compose.yml`). |
| IDE | Visual Studio 2026, or VS Code + C# Dev Kit | VS Code settings, tasks and launch configuration are included in `.vscode/`. |
| Git | any recent | |

Internet is needed **once** for `dotnet restore` and `dotnet tool restore`. After that, building, running,
debugging and testing work offline (packages are cached in `%USERPROFILE%\.nuget\packages`).

## First run (about 10 minutes)

Run from the repository root (PowerShell shown; Bash works the same with `./scripts/db.sh`).

```powershell
# 1. Check the SDK and restore packages and the EF Core tool (needs internet the first time)
dotnet --list-sdks
dotnet restore
dotnet tool restore

# 2. Trust the local HTTPS development certificate (sign-in cookies are HTTPS-only)
dotnet dev-certs https --trust

# 3. (Optional) Use a database other than LocalDB - see docs/CONFIGURATION.md
# dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<connection string>" --project src/BusinessSuite.Web

# 4. Create YOUR development sign-in account (stored outside the repository)
dotnet user-secrets set "DevelopmentSeed:UserEmail" "you@example.com" --project src/BusinessSuite.Web
dotnet user-secrets set "DevelopmentSeed:UserPassword" "<at least 12 chars, upper+lower+digit+symbol>" --project src/BusinessSuite.Web

# 5. ONE TIME: generate the initial database migration, then commit it
./scripts/db.ps1 add InitialCreate

# 6. Run. In Development the app applies migrations and creates your account automatically.
dotnet run --project src/BusinessSuite.Web
# -> open https://localhost:7180 and sign in with the account from step 4

# 7. Run the tests
dotnet test
```

Step 5 exists because migrations must be generated by the real EF Core tooling; see
[src/BusinessSuite.Infrastructure/Persistence/Migrations/README.md](src/BusinessSuite.Infrastructure/Persistence/Migrations/README.md).
Until it is done, the app stops at start-up with the exact command to run, and one test
(`Model_has_no_pending_changes`) fails with the same instruction.

If PowerShell refuses to run scripts: `powershell -ExecutionPolicy Bypass -File .\scripts\db.ps1 add InitialCreate`.

## Everyday commands

| Task | Command |
|---|---|
| Run with hot reload | `dotnet watch run --project src/BusinessSuite.Web --launch-profile https` |
| Build | `dotnet build` |
| All tests | `dotnet test` |
| Tests incl. SQL Server | set `BUSINESSSUITE_TEST_SQLSERVER` first ([tests/README.md](tests/README.md)) |
| New migration | `./scripts/db.ps1 add <Name>` |
| Apply / roll back migrations | `./scripts/db.ps1 update [<TargetMigration>]` |
| Production SQL script | `./scripts/db.ps1 script` → `artifacts/migrations.sql` |
| Format code | `dotnet format` |
| Debug in VS Code | F5 ("BusinessSuite.Web (https)") |

## Solution structure

```text
BusinessSuite/
├─ src/
│  ├─ BusinessSuite.Domain/          Entities and business rules (plain C#, no dependencies)
│  ├─ BusinessSuite.Application/     Use cases, DTOs, Result/Error, interfaces (ICurrentUser)
│  ├─ BusinessSuite.Infrastructure/  EF Core + SQL Server, Identity, auditing, migrations
│  └─ BusinessSuite.Web/             MVC controllers, Razor views, middleware (composition root)
├─ tests/
│  ├─ BusinessSuite.Tests.Unit/        Fast tests + architecture rules
│  └─ BusinessSuite.Tests.Integration/ In-memory web app tests + SQL Server tests
├─ docs/                             Architecture, security, database, workflow, guides
├─ scripts/                          db.ps1 / db.sh (EF Core migrations helper)
├─ tools/sqlserver/                  Optional Docker SQL Server for local development
├─ .github/workflows/ci.yml          Build + test on every push and pull request
├─ Directory.Build.props             Shared build settings (net10.0, nullable, analyzers)
├─ Directory.Packages.props          ALL NuGet versions in one place
└─ global.json                       .NET SDK version pin
```

Each project folder has its own `README.md` saying what belongs there and what never does.
